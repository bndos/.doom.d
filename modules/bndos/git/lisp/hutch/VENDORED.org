* Local modifications

All are marked with =bndos:= in the source; =bndos-local.patch= is the exact
diff against the commit above.

- =hutch-git.el= :: new =:worktree= scope.  Its =:base= is a commit (the
  task's merge-base) and =:head= a tree object snapshotting the whole worktree,
  so the existing diff, file-read and apply plumbing works unchanged.
  =hutch-worktree-scope-function= lets the caller recompute it for the
  bulk-apply content guard.
- =hutch-ui.el= ::
  - =hutch--setup-buffer= takes an optional buffer name (upstream used one
    global =*magit-hutch: code review*= buffer).
  - =hutch-review-title=, =hutch-render-header-functions= and
    =hutch-render-footer-functions= let a host buffer render its own sections
    around the findings.
  - =hutch-review-run= is extracted from =hutch-magit-review=: it runs the
    gptel review for given scopes into a given buffer, dispatching from that
    buffer.  It also fixes an upstream bug where the cancel functions were
    stored in whichever buffer was current, so =C-c C-k= could not cancel.
  - =:worktree= scope name and emoji.
  - Re-rendering keeps point, each window's point and its scroll on the same
    line and column (=hutch--position-spec= / =-restore=), falling back to
    the enclosing section when a hunk's header changed; upstream went back
    to the start of the section.
- =hutch-agent.el= :: =hutch-review-transport= chooses =gptel= (upstream's
  tool loop) or =agent-shell=; agent-shell reviews always run fresh (no cache
  read or write).  =hutch--agent-cancel= also accepts a function.
- =hutch-agent-shell.el= (new file) :: the =agent-shell= transport: one new
  read-only agent-shell session per scope (=hutch-agent-shell-config=, any
  ACP agent; =hutch-agent-shell-model= a model id or =ask= for the session's
  own picker), which ends its reply with a =hutch-review= JSON block in
  =submit_review='s shape; findings then go through upstream's
  normalisation and gates unchanged.  A turn without the block (interrupted,
  or the agent forgot it) pauses the review rather than failing it;
  =hutch-agent-shell-resume= asks the reviewer to finish, and
  =hutch-agent-shell-on-state= reports started / paused / resumed, and
  =hutch-agent-shell-context= adds the caller's text to the prompt, before
  the required output format.

Everything else (gptel transport, prompts, tools, gates, cache, notes,
suggestion states) is upstream as-is.

* Updating

1. Clone upstream at the new commit into an empty directory.
2. Copy the same files over these, then re-apply =bndos-local.patch=
   (=patch -p1 < bndos-local.patch= from this directory) and fix conflicts.
3. Regenerate the patch, update the commit above, and run
   =tests/tasks/run-tests.sh=.
